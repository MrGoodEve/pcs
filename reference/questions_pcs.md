## 1. 66B 码块：与 IEEE 64B/66B / 64B/65B 的对比

### 结论

用户的既有经验是 IEEE 侧口径：**64B/66B 的 2 bit sync header 只有 `01`（数据块）/ `10`（控制块）两种合法值，`00`/`11` 是非法码**。国标 QC/T 1217 的"66B 码块"把这个 2 bit **全部用满**、语义换成"媒体封装包分片位置"，两套机制不是一回事。

术语坑先记一条：**国标里的 "66B码块" = 66 bit 的块**（B 当 bit 用），不是 66 字节；表 A.2/A.3 里"66B码块指示位"等一律如此。

三体系横向对比：

| | **IEEE 64B/66B**（Cl 49/82/119，10G~1.6T 电口） | **IEEE 64B/65B**（Cl 149 = 2.5/5/10GBASE-T1 车载以太网） | **QC/T 1217 66B 码块**（A.2.2.1） |
|---|---|---|---|
| 头宽度 | 2 bit sync header | **1 bit** data/ctrl header | **2 bit 码块指示位 [1:0]** |
| 合法值 | `01`=数据块、`10`=控制块；`00`/`11` **非法** | 0/1 两种 | **`00`/`01`/`10`/`11` 全部合法** |
| 头的语义 | 块内是纯数据还是含控制字符 | 同上（仅这两种） | **分片位置**：`00` 中间分片、`01` 首分片、`10` 末分片、`11` 非分片 |
| 控制信息位置 | 控制块**字节 0 = block type**（15 个合法值），其余字节摆 `/S/ /T/ /I/ /Q/ /LI/ /E/` 控制字符 | 8 字节内压缩控制字符（7 bit 码） | `11` 时复用**负荷低 4 bit 作子指示位**：`0000` 填充 / `xyz0` 物理层控制消息 / `xyz1` 媒体封装小包(≤8 B) |
| 帧边界定位 | 字节级 `/S/`(BT=0x78) 起、`/T/`(0x87,0x99,0xAA,0xB4,0xCC,0xD2,0xE1,0xFF) 止 | 同构（压缩版） | **块级 2 bit 标记**（首/中/尾分片） |
| 空闲机制 | `/I/` 控制字符 | `/I/`、`/LI/` | **物理层填充**（`11`+`0000`，64 bit 全 0）+ 填充 PLDB |
| 顺序约束 | TX 状态机严格 `C→S→D*→T`；`/T/` 后只能接 S/C/LI | 同构 | 只有 `00/01/10` 分片有序；**`11` 块无传输顺序约束** |
| 块锁定/对齐 | 64 个连续合法 sync header 锁定（非法码提供检测） | 1 bit 头 + 同步机制 | **无此机制**：靠同步域（9B/10B `K0/K7` 帧头）+ CRC32 + RX 滑码 |
| 错误标记 | `/E/` 块 + sync header violation | 同构 | 无错误块概念；纠后残余错靠 CRC + 重传（A.2.5 / A.3.5） |
| 后续叠加 | 加扰 → PAM4/NRZ（不再做线路码） | 加扰 → RS-FEC(360,326) → PAM4 | RS-FEC(384,354,9) → **码元交织 L** → 组帧 → 加扰 x³³+x¹³+1 → **9B/10B** → 符号映射 |
| 编码开销 | 2/64 = 3.125% | 1/64 = 1.56% | 2/64 = 3.125%（`11` 块内另有 4 bit 做子指示位） |

### 依据与推导

**① 国标原文（A.2.2.1，ft 769~798 = 印刷 16~17 = PDF 24~25）**，逐条：

- "物理层将媒体封装包分割为 1 个或多个 64 bit 的分片，每个分片经过 64B/66B 编码变成一个 66B 码块"；"一个媒体封装包分片对应的 66B 码块应按照分片顺序进行传输"。
- "66B 码块中，**低 2 位比特为码块指示位**，指示 66B 码块负荷传输的内容"→ 表 A.2：`00` 中间分片 / `01` 第一个分片 / `10` 最后一个分片 / `11` 物理层填充、物理层控制消息、媒体封装小包。
- "码块指示位取值 `11` 时，66B 码块负荷的**低 4 位比特为子指示位**"→ 表 A.3：`0000` 物理层填充（64 bit 负荷全为 0）/ `xyz0`（x,y,z 不能全 0）物理层控制消息，子指示位即该消息的低 4 位 / `xyz1` 媒体封装小包。
- "码块指示位为 `11` 的 66B 码块**无传输顺序约束**，可在任意 66B 码块间传输。"
- A.2.4（ft 979~981 = 印刷 23 = PDF 31）："当存在需要优先传输的高优先级媒体封装包时，节点**应截断**正在传输的低优先级媒体封装包……再继续传输低优先级媒体封装包剩余的 **66B 码块**"→ 截断/恢复粒度 = 66B 码块。
- PLDB 结构（A.2.2.2，ft 799~828 = 印刷 17 = PDF 25）：正向 PLDB = 18 bit 控制 + 48 × 66 bit = **3186 bit = 354 × 9**，与 RS 数据码元数整除 → 一个 PLDB 恰好 48 个 66B 码块。

**② IEEE 侧（属公开资料，本机无 802.3 原文，未逐条核对）**：Cl 49/82/119 的 64B/66B 定义 sync header `01`/`10`、控制块 block type 分类（C：0x1E/0x2D/0x33/0x4B/0x55/0x66；S：0x78；T：0x87/0x99/0xAA/0xB4/0xCC/0xD2/0xE1/0xFF；其余为 E），`/I/`、`/LI/`、ordered set 走字节级控制字符；Cl 149（2.5/5/10GBASE-T1）用 **64B/65B**（`tx_coded<64:0>`，`tx_coded<0>` 为 data/ctrl header）+ RS-FEC(360,326)。**待核**：建议以本机 F 盘的 802.3-2022 副本 / 802.3ch 原文复核后再引用到对外材料。

**③ 由上述推出的差异本质（⚠推论）**：

- IEEE 是"透明比特管道"：PCS 不关心上层帧长，靠 8 字节块内的 `/S/ /T/ /I/` 让 XGMII 的字节/控制流原样穿过，所以 2 bit 头只需回答"这块里有没有控制字符"，**边界信息在字节级**。
- 1217 是"面向包"：媒体封装层自带包头（业务类型/长度/序列号）与 CRC，物理层唯一多余的信息是"这块是某包分片的哪一段"，于是把字节级 `/S/ /T/` **压缩成块级 2 bit**，并把填充/物理层控制消息/小包塞进 `11` 的 4 bit 子指示位。
- ⚠推论 1：**用满 2 bit ⇒ 无非法码 ⇒ 不能靠块头做块锁定/deskew**。Ethernet 的 block_lock 状态机在 1217 里不存在，换成"同步域帧头 + 滑码"；这与内部 PCS 设计里 `pcs_rx_frame_sync_detc`（80 bit 整体滑码、`{K0,K7}`/`{K7,K0}` 帧头）的存在互为印证。
- ⚠推论 2：`11` 块"可乱插"是 A.2.4 优先级截断（截断粒度=66B 码块）与 A.2.5 重传插入的**结构基础**；Ethernet 无等价自由度（`/T/` 后必须接 S/C/LI）。
- ⚠推论 3：`xyz0` 的 4 bit 即物理层控制消息类型的低 4 位，与表 A.8（`0010` 重传 / `0100` 链路重建 / `0110` 休眠控制，`0000` 与 `xyz1` 不可用）自洽 → 解码器可由 66B 码块 `[5:2]` 直接判定控制消息类型，无需另开通道。

**④ 为什么车载另起一套（⚠推论，三条约束）**：线束需 9B/10B 保 DC 平衡与跳变密度（数据中心铜缆不需要）→ 9 bit 码元粒度；EMI/瞬断是突发错 → 必须 RS-FEC + 交织（挡位 4a/5a/6 强制 L=2/4）；业务是图像/音频/控制包而非以太网帧 → 包边界在媒体封装层已知，PCS 只需标分片。

### 对实现的含义

1. 66B 块的解析（指示位/子指示位）在 RX 侧是**纯组合分流**，不需要 IEEE 那种 CGS/block_lock 状态机；块对齐由同步帧 + 滑码负责。
2. 端到端数据通路：媒体封装包 → 64 bit 分片 → 66B 块（首/中/尾/小包） → PLDB(48 块) → RS-FEC → 交织 → 传输帧 → 加扰 → 9B/10B → PAM4 符号映射。
3. 12G 项目的 8b/10b + DME + `tx_train` 帧握手与这套 66B 块/PLDB/9B/10B 是**同一思路的两种尺度**（自定线路码 + 帧式训练 + 块级分流），经验可直接迁移。

## 2. RS 码元交织（A.2.2.4）

### 结论

**以 RS 码元（9 bit）为粒度**，把 L 个 RS 码块的码元**轮流（round-robin）**撒成一条串行码元流。作用是把线上"时间连续"的突发错摊到 L 个互相独立的码块里，**等效把可抗突发长度 ×L，校验开销不增加**；对随机错无增益。

| 项 | 值 | 出处 |
|---|---|---|
| 正向 RS-FEC | RS(384,354,9)，本原多项式 x⁹+x⁴+1；D0~D353 共 354 个 9 bit 数据码元（D0 = PLDB 低 9 位，最先输入），P0~P29 共 30 个校验码元（P0 最先输出）→ **t = 15** | A.2.2.3，ft 829~837 = 印刷 18 = PDF 26 |
| 交织粒度 | **RS 码元**（不是 bit、不是 64B/66B 块） | A.2.2.4，ft 838~842 |
| 交织深度 L | 挡位 1、2、3 → **1**；挡位 4 → **1、2**；挡位 5 → **1、2、4**；挡位 **4a、5a、6（PAM4）→ 2、4（不许为 1）** | 表 A.5，ft 843~848 = 印刷 18 = PDF 26 |
| 谁配置 L | **反向节点**在**反向训练帧**中配置（表 A.17 字节 3~6 的 `[20:19]`：`01`=1 倍、`10`=2 倍、`11`=4 倍）；正向节点发出的正向训练帧中该字段**应固定为 `01`** | 表 A.17，PDF 39 |
| 反向链 | **没有交织级**（A.2.3 顺序中无此项）；反向 RS(73,69,8)，t = 2 | A.2.3，ft 887~977 |
| 延迟代价 | 发送侧要凑齐 L 块才开始轮询输出 → 延迟上界 ⚠ ≈ L × 码块时间（按编码后线速 3840 bit 计：挡位 6 = 300 ns、挡位 4 = 600 ns）→ L=4 时 ≈ 1.2 µs 级；精确值取决于实现（L 路并行编码器 / 单编码器分时 / 流式输出） | ⚠推论，待与 RTL 实现对照（见 §5 Part 1） |

### 依据与推导

- 原文（A.2.2.4）："正向数据传输**应以 RS 码元为粒度**进行交织。交织深度为 L 的 RS 码元交织方式应与图 A.13 相符合。交织深度 L 与正向速率挡位的对应关系应与表 A.5 相符合。"注："RS 码块发送顺序为从 D0~P29。"
- 结构（据图 A.13 的位域识别）：L 个正向 RS 模块（第 1…第 L）各产出码块，经"交织"后按 RS 码元轮询输出，输出串以"L 个 RS 符号"为一组。
- 原理：RS 是硬判决、纠错能力按码元数封顶（t=15）；线束 EMI/瞬断属**突发型**，连续几十个码元错会直接越过 t，整块报废。交织不改冗余、只改**错误在码块间的分布**。
- 规律：速率越高、尤其 PAM4 挡位越强制交织（PAM4 一个符号错可能带出 1 个 10 bit 符号错）。

### L 的选择准则与"带宽需求不大"时的填法

**① 先辨参数归属：L 不是带宽旋钮。** 带宽/吞吐由**正向速率挡位**（协商响应帧 `[8:5]`）+ **PLDB 数量 N**（训练帧 `[18:15]`，4/8/16/32/64）决定；L 不改线速率、不改净荷速率，只改"错误落在哪些码块里"，且**只作用于正向**（反向无交织级）。

**② 标准只给值域、不给准则。** 原文只规定"交织深度 L 与正向速率挡位的对应关系**应**符合表 A.5"，**选 2 还是 4 是工程决定**。按挡位分三层：

| 层 | 挡位 | 含义 |
|---|---|---|
| 唯一合法 | 1、2、3 | L 只能 = 1 → 字段**只能填 `01`**，无选择权 |
| 可选 | 4（1、2）、5（1、2、4） | 在集合内按信道选 |
| 禁止 | 4a、5a、6 | L=1 **非法**，只能 `10`/`11` |

**③ 判据：取"能覆盖最坏突发的最小 L"。** RS 是硬判决、t = 15 码元封顶，交织把 15 个码元的纠错能力摊到 L 个码块 ⇒ **等效抗连续突发 ×L，冗余不变**。先量/仿最坏 EMI、瞬断的连续误码时长（换算成线速比特），再照下表取最小可用 L（L 翻倍 → 交织/解交织缓冲、延迟、编码器实例全翻倍）：

| 挡位 | 速率 | 码块时间 | L 选项 | 可纠连续突发（码元 / 线比特 / 时间；多个 L 用分号隔开） | 交织缓冲上界 ⚠ |
|---|---|---|---|---|---|
| 1 | 2 G | 1920 ns | 只能 1 | 15 / 150 / 75 ns | — |
| 2 | 3.2 G | 1200 ns | 只能 1 | 15 / 150 / 47 ns | — |
| 3 | 4 G | 960 ns | 只能 1 | 15 / 150 / 38 ns | — |

## 3. 表 A.54 "PLDB大小" 口径澄清（原记为 ⚠ 不一致项）

### 结论

表 A.54（GPIO 固定时延触发模式正反向传输时延）里的正向 **3840 bit** / 反向 **730 bit**，与 A.2 推算的 PLDB **3186 / 552 bit** **不矛盾，是口径差**：表 A.54 按 **9B/10B（反向 8B/10B）编码后的线速比特**计，不是 PLDB 本身的位数。

| 环节 | 正向 | 反向 |
|---|---|---|
| RS 编码**前** PLDB（354×9 / 69×8） | 3186 | 552 |
| RS 码块（384×9 / 73×8） | 3456 | 584 |
| **线路码编码后线速位数（384×10 / 73×10）** | **3840** | **730** |

### 依据与推导

- 表 A.54 原文（ft 3914~3940 = 印刷 93 = PDF 101）：正向列 "PLDB大小 3840 bit"，t₂ = 挡位 1(2 G)→1920 ns、2(3.2 G)→1200、3(4 G)→960、4(6.4 G)→600、4a(6.4 G)→600、5(8 G)→480、5a(8 G)→480、6(12.8 G)→300；反向列 挡位 1(0.1 G)、730 bit、7300 ns。
- 算式校验：3840 ÷ 2/3.2/4/6.4/8/12.8 G = 1920/1200/960/600/480/**300** ns —— 与表内逐个吻合；反向 730 ÷ 100 Mb/s = **7300 ns** 吻合。→ t₂ = 位数 ÷ 速率，此时"位数"取的是编码后线速位数。
- 3840 = 384 × 10（384 个 RS 码元各变成 1 个 10 bit 符号）；730 = 73 × 10。而 3186 = 354 × 9、552 = 69 × 8 是 RS 编码器**输入**侧。
- **落盘影响**：① 做 GPIO 固定时延触发（t₃ = T − t₁ − t₂）时，t₂ 应直接取表 A.54 的 ns 值，不要用 3186/速率 重算；② 引用时须写明"按编码后线速比特计"。状态：**待用户确认**（open 0.21）。

## 4. 正向节点与反向节点的协调（A.1.4 / A.1.5 + A.2.6 / A.2.7）

### 结论

1. **角色是固定的非对称分工**：**反向节点 = 发起方 + 配置方**（它虽是低速侧，却是整条链的控制者）；**正向节点 = 应答方 + 落定/汇报方**。每个参数**只有一个决策者**，对端只做确认或回填——不存在"两端各配一半"。做 RTL 时反向侧的"控制者"逻辑（能力匹配、下发正向发射参数、心跳保活）明显重于正向侧。
2. **同步不是逐帧 ack，而是"开环计数同步"**：所有控制帧都带**帧递减计数器**（本批还剩几帧，**末帧必须为 0**），配合固定连发数（请求 40 / 结束 40 / 响应 62500 / 心跳 40）构成**长度确定的突发**，两端各自算出突发何时结束，"发完即切状态"。时间窗（16 ms / 5 ms / 384 µs / 128 µs）只用于失败兜底与回退。
3. **时序是"串行问答 + 轮流静默"**：协商期一问一答；训练期先**正向静默**再**反向静默**（避免两方向同时开车互扰），之后双方**同时**发各自方向的训练帧，先发完的一方发**填充 PLDB** 顶着，直到训练帧收发双向完成，再**同时**进数据传输。
4. **数据传输期有三条并行通路**：时基对齐（同步帧）、重传协调（物理层重传消息 + `Q` / `LTE` / `TE`）、状态迁移（链路重建消息 / 休眠控制消息）。两处状态迁移消息都是"**接受后 500 µs 内进目标状态，无响应 = 保持原状态**"（默认否决语义，不要实现成重试）。
5. **L 的协调是最短的一条**：反向节点在反向训练帧里下发 → 正向节点回 `01` → 训练结束（末帧 = 0）那一刻切到配置值；**运行中没有动态改 L 的通路**（要改只能重训 / 重建链路）。
6. **"正反向"是速率命名、不是主从**：第 3 章定义正向 = 两方向中速率较高者、反向 = 速率较低者；正向节点 = 正向发送 + 反向接收，反向节点 = 反向发送 + 正向接收；哪一侧做正向节点由系统设计指定。

**决策分配矩阵**（逐参数一行，可直接拿去对 RTL）：

| 参数 | 谁定 | 对端做什么 | 载体 |
|---|---|---|---|
| 工作模式（数据传输 / 测试 1-3） | 反向节点提出 | 正向节点在响应帧回执（非 0 → 进测试态） | 请求帧 `[18:16]` / 响应帧 `[19:17]` |
| **正向速率挡位** | 反向节点列能力（11 个 6 bit 训练时长字段，0=不支持） | **正向节点在协商响应帧 `[8:5]` 落定** | 表 A.13 / A.14 |

### 依据与推导

**① 协商：反向节点发起、正向节点落定挡位**（A.1.4，ft 627~657 = 印刷 11~12 = PDF 19~20）

- 原文："链路协商**应**由反向节点发起"；协商确定 4 项——正反向传输速率挡位、工作模式、正反向链路训练静默时长、休眠心跳周期。
- 反向节点：连发 **40** 个协商请求帧 → **16 ms** 收协商响应帧窗口；无响应或"正向速率不匹配"→ 再发 40 个请求帧（循环）；协商成功 → 收完最后一个响应帧后等 **128 µs** → 发 **40** 个协商结束帧 → 进训练。
- 正向节点：收完最后一个请求帧后 **5 ms 之内**开始连发 **62500** 个协商响应帧；发完进 **384 µs** 收结束帧窗口；超时 → 回到收请求帧；**窗口内若又收到协商请求帧，应放弃等结束帧转而处理请求帧**（窗口内双事件仲裁，RTL 须做优先级）。
- 参数落点：请求帧（表 A.13，ft 1202~1272 = 印刷 27~28 = PDF 35~36）承载工作模式、正向静默时长、心跳周期、11 个挡位的训练时长；响应帧（表 A.14，ft 1273~1319 = 印刷 29 = PDF 37）承载协商状态、**正向速率挡位 `[8:5]`**、反向速率挡位 `[10:9]`、反向静默时长、工作模式。即**正向节点是挡位的落定方**，反向速率挡位恒 = 1。

**② 训练：轮流静默 + 同时训练 + 填充 PLDB 顶到收完**（A.1.5，ft 658~671 = 印刷 12 = PDF 20~21）

- 原文顺序："节点**应**首先进入正向静默。在正向静默时间内正向节点**应**不发送信号。正向静默结束后，节点**应**进入反向静默"；两段静默时长由协商确定（请求帧给正向静默、响应帧给反向静默）。
- 静默之后"节点**应**开始正反向链路训练"：正向节点按挡位发 NRZ 训练帧（PAM4 挡位 4a/5a/6 在 NRZ 段之后**再补一段 PAM4**），反向节点在"反向链路训练时间"内只发 NRZ；**反向链路训练时长 = 正向链路训练时长 = 正向 NRZ + 正向 PAM4 训练时长**（表 A.14 以"反向速率挡位 1 的 NRZ 训练时长"字段承载这条等式）。
- "如果节点已完成链路训练帧**发送**，但还未完成链路训练帧**接收**，节点**应**发送**填充 PLDB** 直到完成链路训练帧接收" ⇒ **填充 PLDB 是训练态的正常路径，不是错误处理**；训练成功判据 = 训练帧收发双向完成（训练态只有这一条出口）。

**③ 训练帧里的握手回执**（表 A.17，ft 1365~1419 = 印刷 31 = PDF 38~39）

- `[2]` 过程指示：0=训练进行中、1=训练完成；`[0]` 训练结果（过程指示=1 时有效）：0=失败、1=成功；`[1]` 失败原因：0=K 码或扰码无法同步、1=收端权值无法收敛。
- **判据顺序**：过程指示 = 0 时训练结果无意义、不得当失败判据；失败原因直接分派两类调优动作（前者查 CDC/对齐，后者查 FFE/DFE 自适应）。
- 训练帧 byte0~2 = **24 bit** 帧递减计数器（比协商帧的 16 bit 长），"最后一个训练帧的计数值**应**为 0"——这是两端**对齐训练结束时刻**（同时进数据传输）的依据，无需额外 ack。

**④ 数据传输期的三条并行通路**

- **时基**：正向同步帧（表 A.19，144 bit、CRC32、时基 ID 4 bit）+ 反向同步帧（表 A.20，128 bit、CRC16、时基 ID 2 bit）；相邻两个携带同一时基的同步帧之间间隔的 PLDB 数**应**符合表 A.18（挡位 1、2 ≤16；3、4、4a ≤32；5、5a、6 与反向 ≤64）。
- **重传**（A.2.5，ft 985~1038 = 印刷 23~24 = PDF 31~33）：正向 PLDB 丢 → 反向节点发**正向物理层重传消息**（表 A.9）：单 PLDB 重传 `M`=0（重传 ID = 该 PLDB），多 PLDB 重传 `M`=1（重传 ID = 起始 PLDB，其后全部重传）；退出该 PLDB 的重传接收靠"发 `Q`=0/1 的消息 + 收到 `TE` 值取反的其他 PLDB"组合判定（**两端都可能主动终止**，用 TE 取反 + 上报其他 PLDB 收敛，防死等）。反向 PLDB 丢 → 正向节点发**反向物理层重传消息**（表 A.10，须用正向不可重传 PLDB 承载），前提是反向训练帧 byte7`[0]` 开了反向重传（A.2.5.2 "节点**可**支持反向物理层重传"）。
- **状态迁移**（A.2.6.3 链路重建 ft 1108~1144 = 印刷 26~27 = PDF 34~35；A.2.6.4 休眠控制 ft 1164~1197 = 印刷 27 = PDF 35~36）：链路重建消息（表 A.11）与休眠控制消息（表 A.12）都是请求/响应 + 状态位；**接受 → 收到状态 0 后 500 µs 内进目标状态（响应方在发出状态 0 后 500 µs 内进）；拒绝或无响应 → 保持原状态**（默认否决）。休眠期反向节点每周期连发 40 个心跳帧，正向节点连续 **3 个心跳周期**未收到 → **应**强制退出休眠回链路协商；唤醒复用协商响应帧的协商状态 `110`。
- **重训练 / 休眠 vs 重协商**：重训练（链路重建消息）与休眠用**消息握手**（**应**）；传输异常（无法检测到信号、无法正确接收数据）→ 回链路协商重协商是**本地检测触发、无握手**（**可**）。

### 对实现的含义

1. 反向侧要落"控制者"职责：能力匹配（挡位集合与训练时长）、下发正向发射参数（预加重建议值、PLDB 数量 N、交织深度 L、重传开关）、周期保活心跳；正向侧要能"被配置 + 汇报当前值"（预加重当前值、过程指示/训练结果）。
2. 四组独立定时/窗口 + 窗口内双事件仲裁：16 ms（收响应）、5 ms（启动响应）、384 µs（收结束帧）、128 µs（发结束帧前等待）；384 µs 窗口内"收到请求帧"优先级高于"继续等结束帧"。
3. 训练态出口设计只有"训练成功"一条：发完未收完 → 填充 PLDB；失败退避路径标准未定义（见 §5 Part 2）。
4. 参数快照（L、N、预加重、重传开关）必须在进数据传输前一次性生效；运行中没有改档通路，要改只能重训/重建链路。
