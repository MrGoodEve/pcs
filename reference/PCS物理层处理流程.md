## 1. 处理流程总览（A.2.1，PDF p23~24）

### 结论

**正向链**（图 A.9）：

```
媒体封装包 / 物理层控制消息
  → 64B/66B 编码 → 正向 PLDB 组帧 → 正向 RS-FEC(384,354,9)
  → RS 码元交织（深度 L 按表 A.5） → 正向传输组帧（同步域 + 数据域）
  → 正向加扰（x³³+x¹³+1） → 9B/10B
  → 按协商挡位发送
```

**反向链**（没有交织这一级，且是 8B/10B 不是 9B/10B）：

```
媒体封装包 / 物理层控制消息
  → 64B/66B 编码 → 反向 PLDB 组帧 → 反向 RS-FEC(73,69,8)
  → 反向加扰 → 8B/10B → NRZ 符号映射 → 以反向速率挡位 1 发送
```

**其余各类帧不走完整链**（这点最容易在实现里漏掉）：

| 帧/消息 | 经过的处理 | 出处 |
|---|---|---|
| 正向同步帧 | 正向传输组帧 → 正向加扰 → 9B/10B → 符号映射 | A.2.1, p23；格式见 A.2.7.3 |
| 正向链路训练帧 | 正向加扰 → 9B/10B → 符号映射（**无 64B/66B、无 FEC、无交织**） | A.2.1, p23 |
| 链路协商响应帧 | 正向加扰 → **8B/10B** → NRZ 符号映射，以**挡位 1** 发送 | A.2.1, p23 |
| 反向同步帧 | 反向传输组帧 → 反向加扰 → 8B/10B → 符号映射 | A.2.1, p24 |
| 协商请求帧 / 协商结束帧 / 反向链路训练帧 / 休眠心跳帧 | 反向加扰 → 8B/10B → 符号映射，挡位 1 | A.2.1, p24 |

**符号映射**（A.2.2.8，p27~28）：正向挡位 1~5 用 NRZ；挡位 4a/5a/6 的 NRZ 训练段用 NRZ、PAM4 训练段用 PAM4。
NRZ：`0 → −1`、`1 → +1`；PAM4 按 `[比特1, 比特0]`：`00 → −1`、`01 → −1/3`、`10 → +1/3`、`11 → +1`。

**校验分层（正反向不对称，容易踩）**：

| 层 | 正向 | 反向 |
|---|---|---|
| 码块级 | RS(384,354,9) t=15 **+ 码元交织 L** | RS(73,69,8) t=2，**无交织** |
| PLDB 级 | **没有 CRC**（18 + 48×66 = 3186 = 354×9，无余量） | **有 CRC8**（16 + 8×66 + 8 = 552 = 69×8） |
| 帧级 | 正向同步帧 **CRC32**；协商请求/结束帧、休眠心跳帧 **CRC16** | 反向同步帧 **CRC16**；协商/心跳帧 CRC16 |
| 包级（端到端） | 媒体封装包 CRC：**A 类 CRC32 / B 类 CRC16 / C 类 CRC32**，校验"公共头到 CRC 之前的所有部分" | 同一套包格式，同左 |

⇒ 回答"正向有没有 CRC"：**正向缺的只是 PLDB 级 CRC**；正向同步帧有 CRC32、媒体封装包有 CRC32/16，
物理层内部则靠 **FEC(t=15) + 交织 + PLDB 级重传** 兜。详见 §5。

### 依据与推导

- 原文（A.2.1，PDF p23）：「正向传输的媒体封装包和物理层控制消息应依次经过 64B/66B 编码、正向 PLDB 组帧、
  正向 RS-FEC 编码、RS 码元交织、正向传输组帧、正向加扰、9B/10B、符号映射，然后以协商确定的正向速率挡位发送」；
  「A.2.2.6 定义的扰码移位寄存器用于物理层的**所有**正向加扰」。
- **位序总口径**（A.2 注，PDF p24）：本文件定义的传输帧、控制消息、控制帧和媒体封装包均应按照
  **从最低比特到最高比特**的顺序传输；如无特殊说明，**比特 0 为低位比特**，序列中**最右的比特为最低位**。
  ⚠推论：这条与 FEC 侧「整块降幂发送、p=0 先发」的口径必须显式对齐，否则两端对不上（见 §8）。
- 反向链原文（PDF p24）：「反向传输的媒体封装包和物理层控制消息应依次经过 64B/66B 编码、反向 PLDB 组帧、
  反向 RS-FEC 编码、反向加扰、8B/10B、NRZ 符号映射，然后以反向速率挡位 1 发送」；「A.2.3.5 定义的扰码移位寄存器
  用于物理层的所有反向加扰」。

### 对实现的含义

1. 发送侧不是"选一条通路"而是**按帧类型分流**：媒体封装包/控制消息走完整链，同步帧/训练帧/协商帧各自绕开
   64B/66B 与（或）FEC。分流点在传输组帧之前。
2. 位序只需一套约定（最低比特先传），但要**在每一级都保持**：分片 → 66B 码块 → PLDB → 9bit 码元 → 加扰 → 9B/10B。
3. 加扰器是**正向/反向各一套**（A.2.2.6 / A.2.3.5），且正向的扰码器同时服务数据域与同步帧。

## 2. 64B/66B 编码（A.2.2.1，PDF p24~25）

### 结论

- **分片**：物理层把**媒体封装包**分割为 **1 个或多个 64 bit** 的分片（不是 64 字节）；每个分片经 64B/66B 编码
  变成 **1 个 66B 码块**；同一媒体封装包的多个分片对应的码块**按分片顺序**传输。
- **66B 码块 = 64 bit 负荷 + 2 bit 码块指示位**，指示位在**低 2 位**（`[1:0]`），格式见图 A.10（⚠ 位序待核）。
- **表 A.2 指示位语义**（单独成表，不放列表里，否则 VS Code 不渲染）：

| `[1:0]` | 含义 |
|---|---|
| `00` | 该码块负荷传输媒体封装包的**中间分片** |
| `01` | **第一个分片** |
| `10` | **最后一个分片** |
| `11` | 传输**物理层填充 / 物理层控制消息 / 媒体封装小包** |

- **`11` 时负荷的低 4 位是子指示位**（表 A.3 的列名写作 `[5:2]`）：`0000` 物理层填充（64 bit 负荷全 0）；
  `xyz0`（x,y,z 不全为 0）物理层控制消息，子指示位即该消息的**低 4 位**；`xyz1` 媒体封装小包（≤ 8 字节，
  子指示位为对应媒体封装包的低 4 位）。
- **`11` 类码块无传输顺序约束**，可插在任意两个 66B 码块之间 —— 这是 A.2.4 优先级截断与 A.2.5 重传插入的
  结构基础。

### 依据与推导

原文（PDF p24）：「物理层将媒体封装包分割为 1 个或多个 64 bit 的分片，每个分片经过 64B/66B 编码变成一个
66B 码块」「一个媒体封装包分片对应的 66B 码块应在物理层按照分片顺序进行传输」「66B 码块中，低 2 位比特为
码块指示位」「码块指示位取值 11 时，66B 码块负荷的低 4 位比特为子指示位」「码块指示位为 11 的 66B 码块无
传输顺序约束，可在任意 66B 码块间传输」。表 A.2 / A.3 全文见上（PDF p24~25）。

### 对实现的含义

1. **术语坑先记一条**：本标准的 "66B 码块" 是 **66 bit 的块**（B 当 bit 用），不是 66 字节；"64B/66B" 同理。
   与 IEEE 的 64B/66B（64 字节 + 2 bit sync header）**同形不同义**。
2. RX 侧解析是**纯组合分流**：指示位 `00/01/10` 拼包，`11` 再看子指示位的 4 bit 分三类（填充/控制消息/小包）。
   **没有** IEEE 那种靠非法 sync header 做的 block_lock 状态机；块对齐靠同步帧 + 滑码（见 `questions_pcs.md` §1）。
3. TX 侧需要"分片计数 + 首/中/尾打标 + 末片对齐"：媒体封装包长度不是 64 bit 整数倍时需要填充或小包路径。
4. 「`11` 类可乱插」意味着硬件的接受侧**不能假设 `11` 类码块位置的确定性**（重传/优先级截断都会用到）。

## 3. PLDB（正向 A.2.2.2 / 反向 A.2.3.2）

### 结论

**正向 PLDB = 正向 PLDB 控制（18 bit）+ 正向 PLDB 净荷（48 个 66B 码块）**，控制在前：

```
18 + 48 × 66 = 3186 bit = 354 × 9 bit        ← 正好等于 RS(384,354,9) 的 354 个 9 bit 数据码元
```

**反向 PLDB = 反向 PLDB 控制（16 bit）+ 净荷（8 个 66B 码块）+ 反向 PLDB CRC（CRC8）**：

```
16 + 8 × 66 + 8 = 552 bit = 69 × 8 bit       ← 正好等于 RS(73,69,8) 的 69 个 8 bit 数据码元
```

即：**PLDB 的位数是按 FEC 的 k 个码元反推设计的**（正向 354×9、反向 69×8），这是上位设计的关键约束。

**正向 PLDB 控制字段（表 A.4，18 bit）**：

| 字段 | 比特 | 含义 |
|---|---|---|
| PLDBID | `[11:0]` | 类型 = 0（不可重传/填充）时固定 0；类型 = 1（可重传）时取 0~4095，循环计数 |
| PLDB 类型 | `[12]` | 0 = 填充 PLDB 或不可重传 PLDB；1 = 可重传 PLDB |
| 终止重传 TE | `[13]` | 类型 = 1 时指示是否终止当前重传（取反表示终止）；类型 = 0 时固定 0 |
| 数据类型 | `[14]` | 类型 = 0 时：0 = 填充 / 1 = 不可重传；类型 = 1 时固定 0 |
| 预留 | `[17:15]` | 预留（宜全 0） |

**反向 PLDB 控制字段（表 A.6，16 bit）**：PLDBID `[9:0]`（0~1023）、PLDB 类型 `[10]`、数据类型 `[11]`、预留 `[15:12]`。

**三类 PLDB**（正反向同构）：可重传 / 不可重传 / 填充。可重传的 ID 从 0 起逐 1 增加、循环计数，初传按 ID 顺序发；
**不可重传与填充 PLDB 的 ID 恒为 0**。

### 依据与推导

- 正向（A.2.2.2，PDF p25）：「正向 PLDB 由正向 PLDB 控制和正向 PLDB 净荷构成。正向 PLDB 控制为 18 bit…
  48 个 66B 码块构成正向 PLDB 净荷，其位置在正向 PLDB 控制之后」；表 A.4 见上；「正向可重传 PLDB 的 ID 从 0 开始，
  逐 1 增加，循环计数……正向不可重传 PLDB 和正向填充 PLDB 的 ID 始终为 0」。
- RS 侧（A.2.2.3 注，PDF p26）：「D0~D353 为 354 个 9 bit RS 数据码元，由正向 PLDB 按照从低到高比特顺序分割产生。
  D0 为正向 PLDB 的**低 9 位**比特，最先输入 RS-FEC 编码器；P0~P29 为 30 个 9 bit RS 纠错码元……P0 为最先输出的
  RS 纠错码元」。
- 反向（A.2.3.2，PDF p28）：「反向 PLDB 由反向 PLDB 控制、反向 PLDB 净荷和反向 PLDB CRC 构成。反向 PLDB 控制为
  16 bit…8 个 66B 码块构成反向 PLDB 净荷，其位置在反向 PLDB 控制之后，在反向 PLDB CRC 之前」；
  「反向 PLDB CRC 保护的比特序列由反向 PLDB 控制和反向 PLDB 净荷构成，反向 PLDB CRC 校验生成多项式为表 A.7 中的 CRC8」。

### 对实现的含义

1. **组帧顺序固定**：正向 = 控制在前、净荷在后；反向 = 控制、净荷、CRC 三者依次。
2. **PLDB 只有三种**，且 "填充 PLDB" 是**正常路径**（训练期顶帧、带宽不足时填充），不是错误。
3. 反向 PLDB 比正向多了 **CRC8**，且 CRC 覆盖"控制 + 净荷"（16 + 528 = 544 bit）。CRC 的位序口径见 §5。
4. 与 GPIO 固定时延预算的关系：表 A.54 里正向 3840 bit / 反向 730 bit 是**编码后线速比特**口径
   （3840 = 384×10、730 = 73×10），不能拿 3186/552 去算 t₂（见 `questions_pcs.md` §3）。

## 5. 校验分层与 CRC 口径（PDF p28~29、p31、p101）

### 为什么正向 PLDB 没有 CRC、反向有

⚠推论：**PLDB 的位数被 FEC 的 k 锁死**，没有多余比特放 CRC 就放不下：

```
正向：18（控制）+ 48×66（净荷）= 3186 = 354 × 9   ← 恰好 354 个 9 bit 码元，零余量
反向：16（控制）+  8×66（净荷）+ 8（CRC8）= 552 = 69 × 8   ← 反向控制短 2 bit、净荷少 40 个码块，正好腾出 8 bit
```

再加一处不对称：正向有 t=15 + 交织，反向只有 t=2 且无交织 ⇒ 反向更需要 CRC8 补检错。
正方向则把完整性交给"同步帧 CRC32 + 媒体封装包 CRC + 两级重传"。

### 两级重传各靠什么判错

| 级 | 条款 | 判错依据 | 机制要点 |
|---|---|---|---|
| 物理层 PLDB 级 | A.2.5.1（p31） | "某个 PLDB **未被正确接收**"（⚠标准未写怎么判，见 §7） | 反向节点发正向物理层重传消息：单 PLDB（M=0，重传 ID = 该 PLDB）/ 多 PLDB（M=1，重传 ID = 起始 PLDB）；退出靠 Q 字段 + TE 取反 + 超时重发；LTE 与当前 TE 不同则忽略该消息 |
| 媒体封装层包级 | A.3.5.1（p101） | **包 CRC 不过 + 序列号 + 预设时间内未收到"媒体封装层传输确认包"** | 超时未收到确认 ⇒ 重发（链路序列号保持不变，A 类数据包序列号也保持不变）；B 类包发送完成 = 收到确认或重传次数超门限；收到重复序列号 ⇒ 发确认后丢弃；确认包用 C 类封装包 |

### 三种多项式（表 A.7）

**三种多项式**：CRC8 `x⁸+x⁵+x³+x²+x+1`；CRC16 `x¹⁶+x¹⁵+x²+1`；CRC32
`x³²+x²⁶+x²³+x²²+x¹⁶+x¹²+x¹¹+x¹⁰+x⁸+x⁷+x⁵+x⁴+x²+x+1`（寄存器结构见图 A.18，其中 C0 分别对应 x⁷ / x¹⁵ / x³¹）。

**生成步骤（原文 a~d）**：a) 寄存器初值全 1；b) 把保护序列 D(0)~D(n−1) **逐比特取反**后按序列顺序输入
（D(0) 为保护数据最低位、D(n−1) 为最高位）；c) 输入结束后读寄存器状态 C0~C_{m−1}；d) 把 C0~C_{m−1} **取反**
得到校验序列 B(0)~B_{m−1}（B(0) 为校验字段最低位）。

**★ 本机实测（可作回归向量）**：用「初值全 1 + 输入逐比特取反 + 输出取反」的约定，三个示例**全部复现**：

| 保护序列（示例串，靠左为低位） | 期望校验序列 |
|---|---|
| CRC8：`0110000010100000` | `11110011` |
| CRC16：`01100000101000000110000010100000` | `1011010010100110` |
| CRC32：`0110000010100000011000001010000001100000101000000110000010100000` | `11110110110110100101110001110101` |

⚠**待核（位序读法）**：上面三组向量能被**两种互为镜像**的实现复现（"先送序列哪一端"与"校验字段是否按位翻转"
两处约定可以互换而结果相同），因此**示例本身不足以定死位序**。写 RTL 前必须按 **图 A.18**（PDF p29）
确认 C0 的物理位置与移位方向，或与内部基线实现对齐后再固化。

### 对实现的含义

1. CRC 的**保护范围**要写死：反向 PLDB 是"控制 + 净荷"（544 bit）；PLDB 之外的 CRC（同步帧、媒体封装包自带）
   是另一套，别混用同一个引擎实例。
2. 三个示例直接拿来做**单元测试向量**（含取反与初值），比自算更可靠。
3. CRC8 用于反向 PLDB、CRC16 用于反向同步帧、CRC32 用于正向同步帧（见 A.2.7.3 与表 A.20）。

## 6. 一条完整数据流的账（正向 / 反向）

**正向（媒体封装包）**

```
媒体封装包 → 64 bit 分片 × N（打首/中/尾指示位）
          → 66B 码块 × 48 = 3168 bit
          → +18 bit PLDB 控制 = 3186 bit = 354 × 9 bit
          → RS(384,354,9)：+30 个 9 bit 校验 = 3456 bit = 384 码元
          → 交织 L 路（码元级轮询）
          → 传输帧：同步域 + 数据域（多个 PLDB）→ 加扰 → 9B/10B（×10/9）
          → 3840 线比特/PLDB → 符号映射（NRZ 或 PAM4）→ 按挡位发送
```

**反向（媒体封装包）**

```
媒体封装包 → 64 bit 分片 → 66B 码块 × 8 = 528 bit
          → +16 bit 控制 + 8 bit CRC8 = 552 bit = 69 × 8 bit
          → RS(73,69,8)：+4 个 8 bit 校验 = 584 bit = 73 码元
          → 传输帧 → 加扰 → 8B/10B（×10/8）→ 730 线比特/PLDB → NRZ → 挡位 1
```

⚠推论：3840 与 730 正好是表 A.54 里列的两个数，即 t₂ = 编码后线速位数 ÷ 速率 —— 与 `questions_pcs.md` §3 的口径一致。
