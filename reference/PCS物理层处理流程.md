## 1. 物理层处理流程（A.2.1，图 A.9）

图 A.9 是 **7 条通路 + 一批共享处理块**（方框名按图抄录）：

1. 正向媒体封装包 / 正向物理层控制消息 → 64B/66B 编码 → 正向 PLDB 组帧 → 正向 RS-FEC 编码 → RS 码元交织 →（接第 2 条的共享块）
2. 正向同步帧 → 正向传输组帧 → 正向加扰 → 9B/10B → 符号映射
3. 链路协商响应帧 → 正向加扰 → 8B/10B → 符号映射
4. 正向链路训练帧 → 正向加扰 → 9B/10B → 符号映射
5. 反向媒体封装包 / 反向物理层控制消息 → 64B/66B 编码 → 反向 PLDB 组帧 → 反向 RS-FEC 编码 →（接第 6 条的共享块）
6. 反向同步帧 → 反向传输组帧 → 反向加扰 → 8B/10B → 符号映射
7. 链路协商请求帧 / 协商结束帧 / 反向链路训练帧 / 休眠心跳帧 → 反向加扰 → 8B/10B → 符号映射

要点（按重要性排）：

1. **数据链与同步帧链共用**"传输组帧 / 加扰 / 9B(8B)/10B / 符号映射"这几个处理块（图里只画一次）。
   所以正向加扰器同时服务数据域、同步帧、训练帧。
2. **正向数据链比反向多一级**：正向有 RS-FEC(384,354,9) **和** RS 码元交织；反向有 RS-FEC(73,69,8) 但**没有交织**。
3. **旁路帧不走 64B/66B，也不走 FEC**：正向同步帧/训练帧、协商响应帧、反向同步帧与各类控制帧都从加扰
   （或传输组帧）开始接 ⇒ **分流点在传输组帧之前**。
4. **挡位**：正向数据按协商挡位；协商响应帧、协商请求/结束帧、反向链路训练帧、休眠心跳帧、反向数据链**固定挡位 1**。

**位序总口径**（A.2 注，PDF p24）：本文件定义的传输帧、控制消息、控制帧和媒体封装包均按**从最低比特到最高比特**
的顺序传输；如无特殊说明，**比特 0 为低位比特**，序列中**最右的比特为最低位**。

### 建议（由你定夺）

1. 发送侧不是"选一条通路"而是**按帧类型分流**，分流点在传输组帧之前；RX 侧要按域类型反向拆。
2. 位序只需一套约定（最低比特先传），但要**在每一级都保持**：分片 → 66B 码块 → PLDB → 9 bit 码元 → 加扰 → 9B/10B。
   这条要与 FEC 侧"整块降幂发送、p=0 先发"的口径显式对齐（见 §3、§4）。
3. 加扰器**正/反各一套**，各自服务本方向"所有"加扰对象 ⇒ 不必给每种帧各做一套，但帧间过渡时序要定死（见 §6）。
4. 只有"媒体封装包 / 物理层控制消息"这条链经过 PLDB 与 FEC；其余帧的字段位置见 A.2.7（控制帧）。

## 2. 64B/66B 编码（正向 A.2.2.1，反向按 A.2.3.1 引用）

- **分片**：物理层把媒体封装包分割为 **1 个或多个 64 bit** 的分片（不是 64 字节）；每个分片编码成 **1 个 66B 码块**；
  同一媒体封装包的多个分片的码块**按分片顺序**传输。
- **66B 码块 = 64 bit 负荷 + 2 bit 码块指示位**，指示位在**低 2 位**（`[1:0]`），格式见图 A.10（§0-1）。
- **表 A.2 指示位语义**：

| `[1:0]` | 含义 |
|---|---|
| `00` | 该码块负荷传输媒体封装包的**中间分片** |
| `01` | **第一个分片** |
| `10` | **最后一个分片** |
| `11` | 传输**物理层填充 / 物理层控制消息 / 媒体封装小包** |

- **`11` 时负荷的低 4 位是子指示位**（表 A.3，PDF p24）：

| 子指示位 `[5:2]` | 含义 |
|---|---|
| `0000` | 物理层填充，**64 比特负荷全为 0** |
| `xyz0`（x、y、z 为 0 或 1，但不能全为 0） | 物理层控制消息（见 A.2.6），子指示位即该消息的**低 4 位比特** |
| `xyz1`（x、y、z 为 0 或 1） | **媒体封装小包**（不超过 8 个字节的媒体封装包），子指示位为对应媒体封装包的低 4 位比特 |

- **`11` 类码块无传输顺序约束**，可插在任意两个 66B 码块之间。
- 反向：A.2.3.1 直接引用 A.2.2.1 ⇒ **没有第二条规则**（PDF p28）。

### 建议（由你定夺）

1. **术语坑**：本标准的 "66B 码块" 是 **66 bit 的块**（B 当 bit 用），"64B/66B" 同理；与 IEEE 的 64B/66B
   （64 字节 + 2 bit sync header）**同形不同义**。
2. RX 解析是**纯组合分流**：指示位 `00/01/10` 拼包，`11` 再看子指示位分三类（填充 / 控制消息 / 小包）。
   **没有** IEEE 那种靠非法 sync header 做的 block_lock 状态机；块对齐靠同步帧 + 滑码（见 `questions_pcs.md` §1）。
3. TX 侧要"分片计数 + 首/中/尾打标 + 末片对齐"：媒体封装包长度不是 64 bit 整数倍时要走填充或小包路径。
4. `11` 类可乱插 ⇒ RX **不能假设 `11` 类码块位置确定**；这也是 A.2.4 优先级截断、A.2.5 重传插入的结构基础。

## 3. PLDB 组帧（正向 A.2.2.2 / 反向 A.2.3.2）

**正向 PLDB = 控制（18 bit）+ 净荷（48 个 66B 码块）**，控制在前：

```
18 + 48 × 66 = 3186 bit = 354 × 9 bit
      → 正好等于 RS(384,354,9) 的 354 个 9 bit 数据码元
```

**反向 PLDB = 控制（16 bit）+ 净荷（8 个 66B 码块）+ CRC（CRC8）**：

```
16 + 8 × 66 + 8 = 552 bit = 69 × 8 bit
      → 正好等于 RS(73,69,8) 的 69 个 8 bit 数据码元
```

即 **PLDB 的位数是按 FEC 的 k 反推设计的**（正向 354×9、反向 69×8）—— 上位设计的硬约束，不是巧合。

**正向 PLDB 控制字段（表 A.4，18 bit）**：

| 字段 | 比特 | 描述（缩写） |
|---|---|---|
| PLDBID | `[11:0]` | 类型 = 0（不可重传/填充）时**固定 0**；类型 = 1（可重传）时取 0~4095，初值 0，循环计数 |
| PLDB 类型 | `[12]` | 0 = 填充 PLDB 或不可重传 PLDB；1 = 可重传 PLDB |
| 终止重传 TE | `[13]` | 类型 = 1 时指示是否终止当前重传（初值 0，**取反表示终止**）；类型 = 0 时无意义、固定 0 |
| 数据类型 | `[14]` | 类型 = 0 时：0 = 填充 PLDB，1 = 不可重传 PLDB；类型 = 1 时无意义、固定 0 |
| 预留 | `[17:15]` | 预留（宜全 0） |

**反向 PLDB 控制字段（表 A.6，16 bit）**：PLDBID `[9:0]`（0~1023）、PLDB 类型 `[10]`、数据类型 `[11]`、预留 `[15:12]`。
其中"数据类型"是否生效取决于 **表 A.17 的"反向重传字段"**（`=0` 时数据类型固定 0，见 §0-10）。

**三类 PLDB**（正反向同构）：可重传 / 不可重传 / 填充。可重传的 ID 从 0 起逐 1 增加、循环计数，**初传按 ID 顺序发**；
**不可重传与填充 PLDB 的 ID 始终为 0**。预留字段：原文说明其无实际意义，宜全 0（A.2.2.2，PDF p25）。

**与 FEC 的接口（只列参数，算法见 `算法规格.md`）**：正向按"从低到高比特顺序"切成 `D0~D353`，**D0 = PLDB 的低 9 位、
最先入编码器**；输出 `P0~P29`（30 个 9 bit 校验，**P0 最先输出**）⇒ 384 个 9 bit 码元。反向同理：`D0~D68`
（D0 = 反向 PLDB 的低 8 位）、`P0~P3`（4 个 8 bit 校验）⇒ 73 个 8 bit 码元。

### 建议（由你定夺）

1. 组帧顺序固定：正向 = 控制在前、净荷在后；反向 = 控制、净荷、CRC 三者依次。
2. "填充 PLDB"是**正常路径**（训练期顶帧、带宽不足时填充），不是错误。
3. 反向比正向多 **CRC8**，覆盖"控制 + 净荷"（16 + 528 = 544 bit）；位序口径见 §9。
4. GPIO 固定时延预算（表 A.54）里的 3840 bit / 730 bit 是**编码后线速比特**（3840 = 384×10、730 = 73×10），
   不要拿 3186 / 552 去算 t₂（见 `questions_pcs.md` §3）。

## 4. RS 码元交织与 RX 解交织（A.2.2.4；反向无此级）

- **交织结构（图 A.13，已目视核对）**：L 个正向 RS 码块**并行**进入交织器，输出按**符号位置**成组，
  **每组 L 个符号 = 来自 L 个码块的同一位置**（图上组内下标相同：`P29,P29` … `D1,D1` … `D0,D0`）；
  组与组之间按符号位置推进。等价说法：对 L 行 × 384 列的符号矩阵做**位置转置**后按列输出。
- **发送顺序**：图上码块按 `[P29 P28 … D1 D0]` 画（D0 在最右），结合 §1 的位序总口径 ⇒ 实际按
  **D0 组 → … → P29 组** 发送，与 A.2.2.4 的注一致（发送顺序 D0~P29，PDF p26）
  （此前"校验码元在前"的猜想不成立，**open 0.22 关闭**）。
- **交织深度 L 与挡位（表 A.5）**：挡位 1/2/3 → L=1；挡位 4 → 1 或 2；挡位 5 → 1、2 或 4；挡位 4a/5a/6 → 2 或 4。
  L 由**反向训练帧的"交织深度"字段**配置正向传输（`01`=1 倍、`10`=2 倍、`11`=4 倍，`00` 预留，PDF p39）。
- **RX 解交织**：原文**没有解交织条款**（全文无"解交织"字样）⇒ RX 结构由实现方自己定，只要逆变换对得上即可。
  由图 A.13 的结构可以直接读出一点：第 l 个码块的最后一个符号与其他 L−1 个**同时到达块尾**。

### 建议（由你定夺）

1. **RX 缓存**（这一段都是我的推论，供你判断）：因为 L 个码块的最后一个符号同时到齐，
   **整个交织块（L×384 个符号）收齐前，任何码块都无法开始解码** ⇒ 解交织器固有地要同时驻留 L 个码块。
   于是数据 RAM ≈ **`3186 × L × 2` bit** —— 3186 = 354 个信息符号（校验符号不必进数据 RAM），
   ×L 来自解交织（结构决定的，不是保守取整），×2 = ping-pong；更严格应写成
   `深度 = ⌈L × T_decode / T_block⌉ + 1`（解码在块尾串行做，要么加深缓冲、要么把解码器做成 L 路并行）。
   L=1 约 0.8 KB、L=2 约 1.6 KB、L=4 约 3.2 KB；若按"整码块收全（3456 bit）再算伴随式"则用 `3456 × L × 2`。
2. 伴随式寄存器另算（`L × 30 × 9` bit 量级），边收边算、不占数据 RAM —— 算法细节见 `算法规格.md`。
3. **L 运行时可切换** ⇒ 地址发生器按 L 参数化；切换点放在训练期（缓存要清空/重排）。
4. 地址映射：收到第 j 组的第 l 个符号 → 写进"码块 l 的地址 j"；解交织 = L 块 RAM 并行写 + 串行读。
5. 块对齐不靠 FEC 流恢复，靠**传输帧的同步域**（§5）；反向无交织，按 552 bit × 2 量级缓冲即可。

## 5. 传输帧（正向 A.2.2.5 / 反向 A.2.3.4）

- **正向传输帧 = 1 个正向同步域 + 1 个正向数据域**；同步域传**一个**正向同步帧；数据域传**多个正向 PLDB**，
  数量由**正向链路训练帧指示**。反向传输帧同构（数据域 PLDB 数量由**反向链路训练帧**指示）。
- **同步帧格式**：
  - 正向（表 A.19，PDF p40~41）：144 bit；`有效指示 [75]`（0=时基无效 / 1=有效）、`时基ID [79:76]`、
    `时基信息 [111:80]`、`CRC32 [143:112]`（校验"开始符字段后的其他字段"）。
  - 反向（表 A.20，PDF p41）：128 bit；`有效指示 [77]`、`时基ID [79:78]`、`时基信息 [111:80]`、`CRC16 [127:112]`。
- 同步帧走"传输组帧 → 加扰 → 9B/10B → 符号映射"（**不经 64B/66B、不经 FEC、不经交织**，见 §1）。

### 建议（由你定夺）

1. **帧同步是整条 RX 链的锚**：块对齐 / 解交织的组同步都来自同步域，不需要为对齐另开 RAM。
2. 同步帧的 CRC（正向 CRC32 / 反向 CRC16）与 PLDB 的校验是**两套**，别共用同一个 CRC 引擎实例。
3. 每个数据域的 PLDB 数量是**训练协商出的运行参数**，RX 要按它做边界判断（否则会把同步帧当数据）。

## 6. 数据域加扰（正向 A.2.2.6 / 反向 A.2.3.5）

| 方向 | 生成多项式 | 结构图 | 加扰式 |
|---|---|---|---|
| 正向 | **x³³ + x¹³ + 1**（公式 A.4） | 图 A.15（PDF p27） | `Aₙ = Scrₙ[0] ⊕ Dₙ`（A.5） |
| 反向 | **x³³ + x²⁰ + 1**（公式 A.7） | 图 A.21（PDF p30） | `Aₙ = Scrₙ[0] ⊕ Dₙ`（A.8） |

- **正反两向的多项式不同**（正向抽头 x¹³、反向抽头 x²⁰），别把一套扰码器抄两遍。
- 移位寄存器**状态初始值不应全为 0**；`Aₙ` = 加扰后比特流、`Scrₙ[0]` = 扰码、`Dₙ` = 被加扰比特流。
- 同一方向的扰码器服务**该方向所有加扰对象**：数据域、同步帧、训练帧、协商帧。

### 建议（由你定夺）

1. 两个独立 LFSR（正向抽头 x¹³、反向抽头 x²⁰），都是 33 级；**初值不能全 0**（全 0 会自锁在 0）。
2. 加扰是 GF(2) 逐位异或：收侧同结构、同初值、同步推进即可解扰。
3. 扰码器跨帧是否复位、何时复位、初值如何同步，标准只说"不应全 0" ⇒ 必须在 RTL 里定死并在联调时确认（§0-11）。

## 7. 9B/10B 与 8B/10B 编码（正向 A.2.2.7 / 反向 A.2.3.6）

- **正向数据**用 **9B/10B**（码表 A.2.9.1，PDF p47~62）；**反向数据**用 **8B/10B**（码表 A.2.9.2，PDF p63~71）。
  交叉点：**链路协商响应帧**（正向，挡位 1）用 8B/10B；反向的同步帧 / 协商帧 / 训练帧 / 心跳帧也都用 8B/10B。
- 采用 **PAM4** 时，9B/10B 按图 A.16 的流程：4 路编码器 `B0~B3`（每路 9 bit）。原文注：`B0~B3` 均为 9 比特序列，
  **B0 = 加扰后比特流的第一个 9 bit 序列**，应分流到"对应 PAM4 符号**低位比特 0**"的那台 9B/10B 编码器。
- 线比特换算：正向 384 个 9 bit 码元 ×10/9 = **3840 线比特**；反向 73 个 8 bit 码元 ×10/8 = **730 线比特**（表 A.54 的两个数）。

### 建议（由你定夺）

1. 码表是**承重表**（位序、极性、K 码），必须先渲染 PNG 目视核对再固化 —— 见 §0-7。
2. NRZ 挡位下正向只跑一路 9B/10B；PAM4 挡位（4a/5a/6）要 4 路并行 + 分流，"哪一路对应哪个 PAM4 比特"由图 A.16 定（§0-5）。
3. RX 侧译码应给出**非法码字标志**，它是判断失步的主要信号（标准未规定用法 [注意]）。

## 8. 符号映射（正向 A.2.2.8 / 反向 A.2.3.7）

- 调制方式：**正向**用 NRZ 或 PAM4；**反向**只用 **NRZ**。
- NRZ 映射：`0 → 符号"−1"`，`1 → 符号"+1"`。
- PAM4 映射（比特组合 `[比特1, 比特0]`）：`[0,0] → "−1"`、`[0,1] → "−1/3"`、`[1,0] → "1/3"`、`[1,1] → "1"`。
- 挡位用法：正向挡位 1~5 全用 NRZ；挡位 4a/5a/6 的**训练阶段先用 NRZ、再转 PAM4**。

### 建议（由你定夺）

1. PAM4 下需要 4 路（B0~B3）+ 灰度映射（相邻符号只差 1 bit）；RX 侧需要 3 个判决门限。
2. 反向永远 NRZ ⇒ 反向 AFE/判决电路可以定死，不用预留 PAM4 能力。
3. 挡位切换（NRZ ↔ PAM4）只发生在训练期；切换点与扰码器初值、同步帧的时序要一起定（§0-11）。

## 9. 校验分层与 CRC 口径（跨层）

**校验分层（正反向不对称，容易踩）**：

| 层 | 正向 | 反向 |
|---|---|---|
| 码块级 | RS(384,354,9) t=15 **+ 码元交织 L** | RS(73,69,8) t=2，**无交织** |
| PLDB 级 | **没有 CRC**（18 + 48×66 = 3186 = 354×9，无余量） | **有 CRC8**（16 + 8×66 + 8 = 552 = 69×8） |
| 帧级 | 正向同步帧 **CRC32**；协商请求/结束帧、休眠心跳帧 **CRC16** | 反向同步帧 **CRC16**；协商/心跳帧 CRC16 |
| 包级（端到端） | 媒体封装包 CRC：**A 类 CRC32 / B 类 CRC16 / C 类 CRC32**，校验范围 = 公共头至 CRC 字段之前 | 同一套包格式，同左 |

⇒ 回答"正向有没有 CRC"：**正向缺的只是 PLDB 级 CRC**。[推论]：正向 PLDB 的位数被 FEC 的 k 锁死
（18 + 48×66 = 3186 = 354×9，零余量），装不下 CRC；反向控制短 2 bit、净荷少 40 个码块，正好腾出 8 bit。
再加一处不对称：正向有 t=15 + 交织，反向只有 t=2 且无交织 ⇒ 反向更需要 CRC8 补检错。

**两级重传各靠什么判错**：

| 级 | 条款 | 判错依据 | 机制要点 |
|---|---|---|---|
| 物理层 PLDB 级 | A.2.5.1（p31） | "某个 PLDB **未被正确接收**"（未给判据，见 §0-9） | 反向节点发正向物理层重传消息：单 PLDB（M=0，重传 ID = 该 PLDB）/ 多 PLDB（M=1，重传 ID = 起始 PLDB）；退出靠 Q 字段 + TE 取反 + 超时重发；LTE 与当前 TE 不同则忽略该消息 |
| 媒体封装层包级 | A.3.5.1（p101） | **包 CRC 不过 + 序列号 + 预设时间内未收到"媒体封装层传输确认包"** | 超时未收到确认 ⇒ 重发（链路序列号不变，A 类数据包序列号也不变）；B 类包发送完成 = 收到确认或重传次数超门限；收到重复序列号 ⇒ 发确认后丢弃；确认包用 C 类封装包 |

**三种多项式（表 A.7）**：CRC8 `x⁸+x⁵+x³+x²+x+1`；CRC16 `x¹⁶+x¹⁵+x²+1`；CRC32
`x³²+x²⁶+x²³+x²²+x¹⁶+x¹²+x¹¹+x¹⁰+x⁸+x⁷+x⁵+x⁴+x²+x+1`（寄存器结构见图 A.18，C0 分别对应 x⁷ / x¹⁵ / x³¹）。

**生成步骤（原文 a~d）**：a) 寄存器初值**全 1**；b) 把保护序列 `D(0)~D(n−1)` **逐比特取反**后按序列顺序输入
（`D(0)` 为保护数据最低位、`D(n−1)` 为最高位）；c) 输入结束后读寄存器状态 `C0~C_{m−1}`；d) 把 `C0~C_{m−1}` **取反**
得到校验序列 `B(0)~B_{m−1}`（`B(0)` 为校验字段最低位）。

**本机实测（可作回归向量）**：用"初值全 1 + 输入逐比特取反 + 输出取反"的约定，三个示例**全部复现**：

| 保护序列（示例串，靠左为低位） | 期望校验序列 |
|---|---|
| CRC8：`0110000010100000` | `11110011` |
| CRC16：`01100000101000000110000010100000` | `1011010010100110` |
| CRC32：`0110000010100000011000001010000001100000101000000110000010100000` | `11110110110110100101110001110101` |

[注意]**待核（位序读法）**：上面三组向量能被**两种互为镜像**的实现复现（"先送序列哪一端"与"校验字段是否按位翻转"
两处约定可以互换而结果相同），因此**示例本身不足以定死位序**；写 RTL 前必须按 **图 A.18**（PDF p29）确认
C0 的物理位置与移位方向，或与内部基线实现对齐后再固化（§0-6）。

### 建议（由你定夺）

1. CRC 的**保护范围**要写死：反向 PLDB 是"控制 + 净荷"（544 bit）；同步帧、媒体封装包自带的 CRC 是另外的实例。
2. 三个示例直接做**单元测试向量**（含取反与初值），比自算更可靠。
3. CRC8 用于反向 PLDB、CRC16 用于反向同步帧 / 协商帧 / 心跳帧、CRC32 用于正向同步帧与 A/C 类媒体封装包。

## 10. 一条完整数据流的账（正向 / 反向）

**正向（媒体封装包）**

```
媒体封装包 → 64 bit 分片 × N（打首/中/尾指示位）
          → 66B 码块 × 48 = 3168 bit
          → +18 bit PLDB 控制 = 3186 bit = 354 × 9 bit
          → RS(384,354,9)：+30 个 9 bit 校验 = 3456 bit = 384 码元
          → 交织 L 路（码元级转置，L 个码块一组）
          → 传输帧：同步域 + 数据域（多个 PLDB）→ 加扰 → 9B/10B（×10/9）
          → 3840 线比特/PLDB → 符号映射（NRZ 或 PAM4）→ 按挡位发送
```

**反向（媒体封装包）**

```
媒体封装包 → 64 bit 分片 → 66B 码块 × 8 = 528 bit
          → +16 bit 控制 + 8 bit CRC8 = 552 bit = 69 × 8 bit
          → RS(73,69,8)：+4 个 8 bit 校验 = 584 bit = 73 码元
          → 传输帧 → 加扰 → 8B/10B（×10/8）→ 730 线比特/PLDB → NRZ → 挡位 1
```

[推论]：3840 与 730 正是表 A.54 里列的两个数，即 t₂ = 编码后线速位数 ÷ 速率 —— 与 `questions_pcs.md` §3 口径一致。
